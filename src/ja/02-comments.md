## コメントアウト

説明のためにはまずこれをお教えする必要があります。

Solon言語にはコメントアウトが2種類あります。

### 通常コメントアウト

Solon言語では通常コメントアウトを`//`で行います。
開発者にとって学習コストの少ない設計であることに起因します。

通常コメントアウトは場所を選ばず使用することが可能ですが、
連続して3行を超えると警告として検出されます。これは冗長なコメントを排除するためです。

#### 例

```
// これは通常コメントアウトです
```

### Docコメントアウト

関数やクラスの説明には専用のコメントアウトである、`///`をその関数やクラスの上部に記述します。


指定した場所以外に記述するとエラーとして検出されます。
行数による警告はありませんが、詳細な説明は設計書に分けられるべきであるため、
極力冗長なコメントは控えてください。

#### 例

```
/// 関数の定義方法については後述します。
///
/// @param argument1: Type - 引数1の説明。
/// @param argument2: Type - 引数2の説明。
/// @return ReturnType - 戻り値の説明。
/// @throws ExceptionType - 例外の説明。
def function-name(argument1: Type, argument2: Type) -> ReturnType {  }

/// ここに記述するとエラーです。間を詰めてください。

def function-name2() -> void {  }
```

### ブロックコメントについて

ブロックコメントは**デッドコードの排除**を目的として意図的に実装しません。

ブロックコメントは、多くの場合、一時的に無効化されたコードをコメントアウトするために使われがちです。しかし、デッドコードは長らく放置されることも多々あり、将来的なメンテナンスの妨げとなります。Solonでは、このようなデッドコードはバージョン管理システムで管理されるべきであり、コードベースには残すべきではないと考えています。

また冗長なコメントは警告として検出されます。

開発者はこれに留意し、常にクリーンなコードベースを維持し、できるだけ簡潔なコメントを心掛けてください。
